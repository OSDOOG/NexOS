# การวิเคราะห์ความเข้ากันได้ของสถาปัตยกรรม NexOS Application Runtime

**ผู้จัดทำ**: ทีมสถาปัตยกรรมระบบแกนกลาง NexOS (NexOS Core Architecture Team)  
**สถานะ**: อนุมัติใช้งานแล้ว (ABI v1)  
**แพลตฟอร์มอ้างอิง**: Espressif ESP32-C6 (RISC-V 32-bit RV32IMAC @ 160MHz, 512KB SRAM, 4MB Flash)

---

## 1. บทสรุปสำหรับผู้บริหาร (Executive Summary)

ตามข้อกำหนดใน **Master Specification ส่วนที่ 10** เอกสารฉบับนี้ทำการวิเคราะห์ เปรียบเทียบประสิทธิภาพ และวัดผลตัวเลือกสถาปัตยกรรมรันไทม์ (Runtime Architectures) ทั้ง 6 รูปแบบ สำหรับการโหลดและรันแอปพลิเคชันของผู้พัฒนาบน ESP32-C6 ผ่านหน่วยความจำภายนอก (MicroSD/Flash)

จากการประเมินผลด้านประสิทธิภาพ ความเร็ว การใช้หน่วยความจำ RAM ความซับซ้อนของตัวโหลด (Loader) ความปลอดภัย และข้อจำกัดของฮาร์ดแวร์จริง ทางทีมงานได้ตัดสินใจเลือก **สถาปัตยกรรมรูปแบบที่ 2 และ 3 (Relocatable Native Module with Syscall Dispatch Vector)** เป็นมาตรฐานสำหรับ **NexOS Application Platform v1.0**

| :--- | :--- | :--- | :--- | :--- | :--- | :--- |

| **ภาระการใช้ RAM (SRAM)** | ต่ำสุด (Code+Data) | **ต่ำสุด (Code+Data+BSS)** | ต่ำสุด | สูงมาก (>80 KB สำหรับ VM) | สูงมาก (>60 KB รันไทม์) | ปานกลาง (>40 KB) |
| **ภาระการใช้ Flash** | ไม่มี | **ไม่มี** | ไม่มี | สูง (เอนจินของ VM) | สูง (เอนจิน Wasm) | ปานกลาง |

| **การแยกส่วนหน่วยความจำ** | ไม่มี (เข้าถึงพอยน์เตอร์ตรง) | **ป้องกันผ่าน Kernel Syscall** | ป้องกันผ่าน Kernel Syscall | แซนด์บ็อกซ์ | แซนด์บ็อกซ์ | ผสมผสาน |

## 3. การประเมินผลเชิงลึกของแต่ละตัวเลือก

### ตัวเลือกที่ 1: ไบนารีเนทีฟแบบกำหนดตำแหน่งตายตัว (Native RISC-V Executable - Absolute Addresses)
- **แนวคิด**: คอมไพล์แอปพลิเคชันไปยังแอดเดรสหน่วยความจำแบบคงที่ (เช่น `0x40820000`)
- **ข้อบกพร่องร้ายแรง**:
  1. โหลดแอปพลิเคชันได้เพียง **แอปเดียว** ในเวลาเดียวกัน
  2. หากมีการอัปเดตเคอร์เนลแล้วขนาดเปลี่ยน แอดเดรสจะคลาดเคลื่อนและทำให้แอปพลิเคชันที่เคยบิลด์ไว้พังทั้งหมด
  3. ไม่สามารถแยกส่วนความปลอดภัยหรือตรวจสิทธิ์ได้
- **ข้อสรุป**: **ปฏิเสธ (REJECTED)**

### ตัวเลือกที่ 2: Relocatable Native Module พร้อม Kernel Syscall Table (สถาปัตยกรรมที่เลือกใช้)
- **แนวคิด**: โค้ดแอปพลิเคชันถูกคอมไพล์โดยใช้เซกชันที่สามารถย้ายตำแหน่งได้ (`-fPIC` หรือ Relative Offsets) และเชื่อมโยงผ่านสัญลักษณ์ภายนอกเพียงตัวเดียวคือ `g_nex_syscall_table`
- **หลักการทำงานบน ESP32-C6**:
  1. ตัวโหลดแอปพลิเคชันของ NexOS อ่านไฟล์ `.app` จาก MicroSD Card
  2. จองบล็อกหน่วยความจำ SRAM ขนาดเท่ากับ `code_size + data_size + bss_size` จากเคอร์เนล Heap
  3. ส่งแอดเดรสของตาราง `nex_syscall_table_t` ของเคอร์เนลไปยังฟังก์ชันทางเข้า `_nex_app_start` ของแอปพลิเคชัน
  4. แอปพลิเคชันประมวลผลด้วยความเร็วเนทีฟเต็ม 160MHz ของฮาร์ดแวร์
  5. การเรียกใช้ I/O ทั้งหมด (GPIO, UART, เครือข่าย, สตอเรจ) จะผ่านฟังก์ชัน Syscall ของเคอร์เนลซึ่งมีการตรวจสอบสิทธิ์ที่ประกาศไว้ใน `nexos.toml` ก่อนเสมอ
- **ข้อดี**:
  - ไม่มีภาระของเอนจิน VM แม้แต่ไบต์เดียว
  - เหลือพื้นที่ SRAM มากกว่า 450+ KB สำหรับประมวลผลงานของแอปพลิเคชัน
  - เข้าถึงความสามารถของฮาร์ดแวร์ได้ 100% (WiFi 6, BLE 5.3, Hardware Crypto)
- **ข้อสรุป**: **อนุมัติและนำมาใช้เป็นสถาปัตยกรรมหลัก (APPROVED & ADOPTED)**

### ตัวเลือกที่ 4 และ 5: Bytecode Virtual Machine / WebAssembly
- **แนวคิด**: รันโค้ดผ่านตัวแปลงคำสั่ง (Wasm Micro Runtime / eBPF / Lua)
- **ข้อบกพร่องร้ายแรง**:
  1. **ขาดแคลนหน่วยความจำ RAM**: รันไทม์อย่าง WAMR หรือ Lua ต้องการ RAM อย่างน้อย 40 KB ถึง 90 KB เพียงเพื่อรันตัวเอนจิน ซึ่งบนชิป ESP32-C6 เมื่อเปิดใช้สแต็ก WiFi 6 และ BLE จะเหลือ RAM ให้ใช้ประมาณ ~180 KB เท่านั้น การเสีย RAM ครึ่งหนึ่งให้เอนจิน VM จะทำให้แอปพลิเคชันแทบทำงานจริงไม่ได้
  2. **ประสิทธิภาพลดลง**: ความเร็วช้าลง 10 ถึง 20 เท่า ส่งผลกระทบอย่างรุนแรงต่อการขับหน้าจอ SPI ความเร็วสูง และการประมวลผล DSP แบบเรียลไทม์
- **ข้อสรุป**: **ปฏิเสธสำหรับแกนหลัก (สงวนไว้พิจารณาสำหรับแซนด์บ็อกซ์สคริปต์ในอนาคต)**

## 4. ข้อกำหนดสำหรับ ABI v1

- **รูปแบบของฟังก์ชันทางเข้า (Entry Point Signature)**:
  ```c
  int _nex_app_start(const nex_syscall_table_t *table);
  ```
- **การตรวจสอบสิทธิ์ฮาร์ดแวร์ (Permission Checking)**:
  ฟังก์ชัน Syscall จะตรวจสอบบิตสิทธิ์ของผู้เรียกก่อนอนุญาตให้เข้าถึงพินหรือวงจรฮาร์ดแวร์จริง
- **ขอบเขตหน่วยความจำ (Memory Boundaries)**:
  ขนาด Stack และ Heap ถูกประกาศใน `nexos.toml` และได้รับการตรวจสอบก่อนจัดสรรพื้นที่ SRAM เพื่อเริ่มรัน Task
